Local AI Infrastructure

optmod

A local OpenAI-compatible routing proxy that selects the optimal LLM for each request — transparently, within a single HTTP call.

Python 3.11+ FastAPI httpx async DeepSeek + OpenRouter PerfRouter (XGBoost) sentence-transformers Laya uv

Status as of 24 October 2026

💡 Motivation

Every LLM call has a cost — in latency, money, or both. Most agentic frameworks pick one model and use it for everything. optmod sits between your agent and the models, predicting which model will handle each request well and routing it to the cheapest one that qualifies, in a few milliseconds and with no LLM call — escalating transparently on failure, all within a single HTTP call the agent never sees.

The key insight is same-turn escalation: the calling agent sends one request and receives one response. optmod may silently try multiple models internally — starting cheap, stepping up only when needed. This is something a Hermes plugin or client-side retry loop cannot provide, because those approaches require a second round-trip from the agent.

The proxy is entirely local. It requires no authentication, stores nothing in a database (append-only JSONL log), and is fully OpenAI wire-format compatible — meaning any agent that works with OpenAI can be pointed at optmod with a one-line config change.

⚡ How a request flows

Agent ──▶ optmod :8765 POST /v1/chat/completions
│
├── 1. Parse Pydantic validation
├── 2. Extract features <1ms, regex only
├── 3. Session pin hard pin (0–300 s) reuses the last model, skips the router
├── 4. Route perf_router: task type → XGBoost quality → model
│ └── Laya difficulty tier sets δ and the cost cap for this request
├── 5. Mutate context /think prefix, tool-output compression
├── 6. Forward httpx async, one client per base_url
│ └── on error → escalate to the next tier (at most 2 escalations)
└── 7. Log + return one JSONL line, one response

Non-retryable errors (auth, bad request) short-circuit immediately. Retryable errors (rate limit, server error, timeout) trigger escalation to the next tier, at most twice per request (escalation.max_escalations: 2).

🧭 Routers

Five routers sit behind one BaseRouter interface and swap at runtime with POST /optmod/router/{name} — no restart. perf_router is the default. Whatever the router, the agent's endpoint never changes.

perf_router default

sentence-BERT matches the query to PerfRouter's task types, XGBoost predicts each model's quality, and the cheapest eligible model within the quality band wins. Benchmark-driven: a new model needs a YAML entry, not a benchmark run.

rule_based

9 deterministic rules evaluated in order (table below). Fully interpretable. Safe fallback target if anything goes wrong.

trouter

Neural network router. sentence-BERT encodes the query; a lightweight MLP scores each model weighting quality and cost. Loads trouter_weights.pt once at startup.

decision_tree

scikit-learn tree trained on WildClawBench. Falls back to rule_based if routing_policy.pkl is absent.

passthrough

Always routes to the primary model (deepseek/deepseek-v4-flash). No classification. Useful for baseline comparison.

How perf_router decides

# Step What happens
1 Classify The last 3 user messages are embedded with MiniLM and matched to the top task types. Below min_similarity (0.20) the query is ambiguous and goes to the cheapest eligible model.
2 Predict XGBoost predicts each model's quality on those task types from its benchmark feature vector.
3 Filter Models that fail the context window, vision or cost cap are dropped. The cap is the baseline's price × cost_cap_multiplier (2.0; baseline deepseek-v4-flash).
4 Choose With δ > 0 (degradation_threshold, 0.15): the cheapest model within δ of the best predicted quality. With δ = 0: the highest quality − α·cost (α = 0.3). A soft session pin credits the previous model with its cache savings.

rule_based: the 9 rules

Rules are evaluated in order — first match wins. Features are extracted from the request in <1ms using compiled regex patterns; no ML, no file I/O, no network calls during classification.

# Condition Routes to Reason
1 All models already tried oracle All tiers exhausted
2 Oracle rate-limited + already tried reasoning Step down gracefully
3 difficulty == hard OR tokens > 8000 oracle Hard / long context
4 task_type == reason AND not easy reasoning + /think Non-trivial reasoning → thinking mode
5 task_type == code AND difficulty == hard oracle Hard code problems
6 task_type ∈ {extract, summarize} AND tokens < 3000 fast Cheap short tasks
7 has_tools == true AND task_type == tool_call reasoning Tool call handling
8 language == he (Hebrew detected) reasoning Hebrew content
9 Default fast Low-cost default (confidence 0.7)

🎚 Laya difficulty tier new

PerfRouter ranks models per task type, so a trivial question and a hard one of the same type get the same ranking, and one static quality band (δ) and cost cap apply to both. Laya — a small local decision model that answers a typed question in one forward pass, with no generation — labels each routed query easy, medium or hard, and the tier sets δ and the cost cap for that one request. Easy queries accept a wider band and land on cheaper models; hard queries get a narrow band and a higher cap.

Tier δ (quality band) Cost cap Effect
easy 0.25 2.0× Accept any model within 25% of the best: cheaper models qualify more often
medium 0.15 2.0× Same as the static default
hard 0.03 4.0× Stay close to the best predicted quality, and let pricier models become eligible

Tier values are placeholders, to be tuned from shadow data. δ must stay above 0 for every tier: in PerfRouter δ = 0 switches to quality − α·cost, which is not "best quality".

Modes

off

Identical to having no laya block: the static δ and cost cap apply.

shadow current

Route with the static values. When the tier's values differ, a second route() call records the model Laya would have chosen (laya_shadow_model).

active

Apply the tier's δ and cost cap when Laya answers with confidence ≥ min_confidence (0.5). Otherwise fall back to the static values.

Guardrails

Bounded latency

80 ms timeout per call; 3 consecutive errors, timeouts or slow calls open a circuit breaker for 60 s; a 512-entry memo serves repeated queries.

Fails soft

Laya is an optional extra (uv pip install -e '.[laya]'). A missing package or failed load reports unavailable; it never raises.

Observe-only when ambiguous

Below MiniLM's min_similarity the query goes to the cheapest model as before; the tier is logged but not applied.

Measured

Each log line carries laya_tier, laya_confidence, laya_ms, laya_applied, laya_shadow_model, effective_delta, effective_cost_cap. Query text is never logged.

Status

Done: phase 1 (embedded backend — Laya runs inside the optmod process) and phase 1b (low-similarity queries classified, observe-only). Not started: phase 2, a remote backend calling laya-serve over HTTP; phase 3, routing confidently-hard low-similarity queries to a configured model instead of the cheapest. Switch modes at runtime with POST /optmod/laya/{off|shadow|active}. Plan: optmod-spec/plans/laya-difficulty-tier.md.

📌 Session pinning

Multi-turn conversations stick to the same model while the provider's prompt cache is still warm, so later turns keep cached-read pricing instead of paying full input cost. A session is identified by the SHA1 of the first user message.

Hard pin · 0–300 s

Bypass the router entirely and reuse the previous model.

Soft bonus · 300–1800 s

perf_router scores normally, but the previous model is credited with its observed cache savings.

Fresh · over 1800 s

The pin is dropped and routing starts from scratch.

The pin is always overridden when the pinned model errors or is rate-limited, when the request has images and the pinned model has no vision, when the model was removed from the registry, or when the conversation outgrows its context window (then it moves to the closest larger-context model). Pin state is in memory only and clears on restart. Each log line records the outcome in pin_state. Pinning can be switched off at runtime with POST /optmod/session-pin/off.

✂️ Context mutators

Post-routing transforms of the message list. Mutators always return a new list and never raise.

noop

Identity passthrough.

thinking_mode

Prepends /think to trigger chain-of-thought. Selected automatically for models marked thinking_mode.

tool_result_compressor

RTK-style compression of tool outputs: git diff and status, grep, ls and tree, build and test output, log de-duplication, smart truncation. Saves tokens on top of routing. Off by default; toggle with POST /optmod/compressor/{on|off}.

🔒 Design constraints

<1ms feature extraction

No ML, no file I/O, no network inside FeatureExtractor.extract(). All regex compiled at import time.

One HTTP client per base_url

httpx.AsyncClient instances are cached by base_url. Never created per request. Connection pools are reused.

Routers never raise

All exceptions inside route() are caught. On any error the router falls back to passthrough silently.

Immutable message mutation

Mutators return a new message list. Never modify the original in-place. Pydantic model_copy(update=...) used throughout.

Append-only log

One JSONL line per request, written with threading.Lock. The file is never rewritten; clearing it is an explicit endpoint.

No secrets in code

API keys are resolved from environment variables at startup (api_key_env per provider in config.yaml). Never hardcoded.

Optional parts fail soft

PerfRouter, TRouter and Laya are optional extras. If one is missing, its router falls back silently or Laya reports unavailable.
